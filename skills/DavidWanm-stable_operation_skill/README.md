一个 opencode 技能：让 AI 在加新功能的时候，别顺手把旧代码拆了。

## 它解决什么问题

AI 编码最常见的翻车姿势之一：你说"加个导出 CSV 的功能"，它把整个 service 层重构了。功能倒是加了，原有的接口 500 了，改动散在七八个文件里，commit message 还写着 `feat: add CSV export`。

这个 skill 不追求写出更聪明的代码，只盯一件事：**旧功能别坏**。它不改变模型的能力，只约束模型改代码时的行为边界。

## 工作机制

三个概念，一套决策：

**存量代码**：任务开始前已存在的任何文件、函数、接口、配置。你这次没创建的，都算存量。
**任务范围**：完成请求所需的最小文件集。模型动手前必须先声明"我要动 X、Y，不动 Z"。
**优先级**：规则冲突时按 `用户明确指令 > 任务范围 > 存量保护` 裁决。

模型每次改代码前按决策树走一遍：

```
用户明确下令要改？
 ├─ 是 → 直接执行
 └─ 否 → 改动在任务范围内？
           ├─ 是 → 执行（只做加法、保持行为）
           └─ 否 → 触及存量代码 → 停下，说明改动与风险，等确认
```

## 核心规则

1. **加法优先**：新功能写新文件，或在现有函数末尾追加逻辑，不改写原有函数；新参数必须带保持原行为的默认值。
2. **存量不可动**：不删除、不改名、不改签名的存量代码，除非用户点名要改。
3. **行为守恒**：相同输入产生相同输出，测试、API 响应、CLI 输出、边界情况一律保持一致。
4. **行为变化加开关**：新功能改变旧行为时用 feature flag 隔离，默认值由用户意图决定，并在动手前说明。
5. **先建基准**：改动前先 commit 或记录 `git status`，没有基准就无法验证差异。
6. **交工前验证**：跑测试、逐行审 diff、确认无文件被删。跑不了测试就明说，不许假装通过。

## 安装

把仓库放进 opencode 的 skills 目录：

```
.opencode/skills/stable-operation-skill/
```

或配置 `opencode.json` 指定 skills 路径：

```json
{
  "skills": {
    "paths": [".opencode/skills"]
  }
}
```

重启 opencode 后按需自动加载。

## 适用边界

- **适合**：已有存量代码的迭代开发、加功能、修 bug。
- **不适合**：绿场新项目（没有存量可保护）；明确授权的大规模重构（建议临时停用）；需要"代码绝对不会被改"的硬保障（那要靠 git hook / CI，prompt 层面做不到）。

## 局限

- 纯 prompt 约束，不是沙箱，模型理论上可以无视，效果取决于模型对指令的遵循能力。
- 验证和回滚依赖 git；非 git 仓库时退化为"改前复制副本、改后逐行对比"的手动流程。
- 只保护存量代码，对模型新增的代码本身没有约束力。

## 排障

**模型还是改了不该改的代码？**
- 确认 skill 已加载（日志里应有加载记录）。
- 检查指令里有没有模糊授权词，比如"优化一下"——这些会被模型当作放行信号。
- 换指令遵循能力更强的模型。

**模型问得太多？**
- 正常，它宁愿多问也不乱改。直接说"这个可以改"即可授权。

**想锁死某个文件？**
- skill 管不到那么硬，用 git hook 或文件只读更可靠。
