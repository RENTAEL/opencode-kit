# Contributing to senior-prompt-engineer

Thanks for your interest in improving this skill! Contributions of all sizes are welcome.

## Ways to contribute
- **Improve the Spec workflow or techniques** in `SKILL.md` / `references/`.
- **Add or sharpen domain playbooks** in `references/domain-playbooks.md`.
- **Add before/after examples** in `references/examples.md`.
- **Fix typos, clarify wording, improve docs.**
- **Report bugs or request features** via Issues.

## Important: do NOT commit personal learnings
`LEARNINGS.md` is git-ignored on purpose. It is each user's **local, private** memory.
- Never add `LEARNINGS.md` to a commit or PR.
- If you want to propose a *generally useful* rule, add it to `LEARNINGS.template.md` (the shared seed) or to the relevant section of `references/domain-playbooks.md` instead.

## Workflow
1. Fork the repo and create a branch: `git checkout -b my-improvement`.
2. Make your change. Keep `SKILL.md` under ~500 lines (use `references/` for depth - this is "progressive disclosure").
3. Run a quick self-check: does the change keep instructions clear, specific, and non-duplicated?
4. Commit with a clear message and open a Pull Request describing the *what* and *why*.

## Style guidelines
- Keep instructions concrete and testable ("default dark theme unless asked") over vague ("make it better").
- Prefer small, focused PRs.
- Match the existing tone and Markdown structure.
